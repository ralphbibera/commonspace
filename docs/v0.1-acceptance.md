# v0.1 acceptance ledger

This ledger helps maintainers find the evidence for v0.1 behavior and decide what to rerun before a release. Requirement IDs refer to the [Product specification](product-spec.md).

The tables record the **2026-08-31 product acceptance snapshot**. `Verified` means that snapshot recorded automated contract, service, or UI coverage; it does not mean the current checkout or a new release candidate has passed those checks. Release-gate instructions were updated on **2026-09-05**.

The current specification also includes **CON-11**, which requires workspace-wide model and reasoning configuration with no Channel overrides. Coverage added after the historical snapshot is listed separately below.

Use the tables to locate focused coverage, then run the [current release gates](#current-release-gates) against the exact candidate. Real-runtime and real-LaunchAgent checks are separate from credential-free CI and archive smoke checks.

## Current release gates

These commands define the required checks. A release record must include results from the candidate being shipped; the historical tables are not a substitute.

| Command | What it checks |
| --- | --- |
| `pnpm check` | Biome, ESLint, types, unit and integration tests, the full Storybook browser suite, and production application and Storybook builds. |
| `pnpm verify:live` | A fresh production build in separate and installed serving modes; desktop Chromium startup; keyboard search and navigation; `@@project` composition; Light/Dark palettes through the appearance controls. |
| `pnpm release:pack` and `pnpm verify:release` | A platform archive and checksum, followed by extraction and a runtime smoke test outside the checkout. Packaging tests live in `tests/release-package.spec.mjs`; the release workflow repeats archive checks for macOS ARM64, macOS x64, and Linux x64. |
| `pnpm verify:service` | A real source clone, install, build, LaunchAgent definition, update, and rollback under an isolated temporary macOS home. `launchctl` commands and health responses are substituted; this does not start a real LaunchAgent. |
| `pnpm verify:acp` | Real installed Codex and Hermes startup and exact native-session resume. |
| `pnpm verify:acp:mcp` | Real Codex and Hermes reading scoped context, posting visible progress, and returning the expected final reply. |

Before publishing a distribution build, install the candidate archive on a clean supported macOS account and manually check real LaunchAgent startup, browser access, status, update, and rollback. Separately run the opt-in runtime checks with local credentials. Record both sets of results using [Releasing](releasing.md#check-the-real-integrations); credential-free CI and substituted service checks cannot establish them.

See [Releasing](releasing.md) for archive packaging and the complete release process.
